# Changelog — EdgeFirst Yocto for PHYTEC i.MX 95

All notable changes to this branch are documented here. For per-package details, see the [meta-edgefirst CHANGELOG](https://github.com/EdgeFirstAI/meta-edgefirst/blob/main/CHANGELOG.md).

## [Unreleased]

- Advance `meta-edgefirst` to `c9491ea` and `meta-edgefirst-phytec` to `c6dc24c`: the Neutron NPU now runs eIQ Neutron SDK 3.2.3, which needs a kernel change NXP's compatibility matrix does not mention. 3.2.x firmware replies `0xA1` to a mailbox reset where PHYTEC's 6.18.20-based driver expects `0x0` and spins until its retry budget runs out, leaving the NPU unusable, so the vendor layer backports NXP commit `a7dcf897` verbatim: `RESET_VAL` becomes `0xA1`, a `POLL` sentinel precedes each request, a reset is issued once the core boots so the first inference of a boot does not take the stuck-NPU path, and the firmware reply is snapshotted before that reset clobbers the mailbox registers. The reply value is a version lock rather than a negotiation, so this kernel requires 3.2.x firmware; the `neutron` recipe installs firmware, library and headers from one SDK tree, so a rootfs cannot mix generations.
- The image payload is installed by `packagegroup-edgefirst-phytec` through a `phytec-headless-image` bbappend in the vendor layer rather than from `local.conf`, so a build is reproducible from a manifest sync alone. `meta-edgefirst` supplies the capability packagegroups (`-npu`, `-graphics`, `-codec`, `-camera`, `-studio`, `-diagnostics`) and the vendor layer composes them, adding meta-ampliphy's own `packagegroup-camera` and `phycam-imx95-dewarp-configs`. The image carries no GStreamer: `packagegroup-edgefirst-codec` installs the WAVE5 firmware for the V4L2 memory-to-memory codec path, and `packagegroup-edgefirst-gstreamer` is a single opt-in switch that is not installed. Removes 366 packages and takes the bundle from 369 MB to 329 MB. Both projects move in one commit because the vendor layer's packagegroup references groups that exist only in the newer `meta-edgefirst`.
- Add `meta-edgefirst-phytec` and advance `meta-edgefirst` to `635d4be`: the PHYTEC-specific RAUC wiring — the device keyring bbappend, the bundle signing include, the two bundle bbappends and the CA and publish scripts — now lives in a PHYTEC vendor layer alongside `meta-edgefirst-ezurio` and `meta-edgefirst-torizon`, leaving `meta-edgefirst` vendor-neutral. RAUC is a PHYTEC-only update mechanism, so the keyring bbappend's `update` override matched no other vendor's distro. The new layer also carries the `ClientIdentifier=mac` drop-in that holds a DHCP lease stable across A/B slot activations. Both projects move in a single commit: adding the layer without bumping the pin duplicates every bbappend, and bumping the pin without adding the layer drops the RAUC wiring.
- Document the i.MX 95 / i.MX 8M Plus release-line split in the README: PD26.1.y is published against two Yocto releases, so there is no single Yocto version that tracks it. Records the SoC-to-branch mapping, that each line needs its own workspace because wrynose and walnascar differ in core-layer layout, why the i.MX 8M Plus machine configs present here do not build, and the specific upstream condition under which the two branches could merge.
- New branch `edgefirst-phytec-imx95-PD26.1.y`: PHYTEC's `BSP-Yocto-NXP-i.MX95-PD26.1.y` manifest (NXP 6.18.20-2.0.0, wrynose) with meta-edgefirst added from `main`, for `imx95-phyflex-libra-rdk-2`.
