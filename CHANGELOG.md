# Changelog — EdgeFirst Yocto for PHYTEC i.MX 8M Plus

All notable changes to this branch are documented here. For per-package details, see the [meta-edgefirst CHANGELOG](https://github.com/EdgeFirstAI/meta-edgefirst/blob/main/CHANGELOG.md).

## [Unreleased]

- Advance `meta-edgefirst` to `c9491ea` and `meta-edgefirst-phytec` to `c6dc24c`: the image payload is now installed by `packagegroup-edgefirst-phytec` through a `phytec-headless-image` bbappend in the vendor layer, so a build is reproducible from a manifest sync with nothing in `local.conf`. `meta-edgefirst` gains the capability packagegroups (`-npu`, `-graphics`, `-codec`, `-camera`, `-studio`, `-diagnostics`) describing what a capability is, while the vendor layer decides which ones this board family ships. The image carries no GStreamer: EdgeFirst reaches the camera through V4L2 and the video encoder and decoder through the V4L2 memory-to-memory API, so `packagegroup-edgefirst-codec` carries the codec userspace — `imx-vpu-hantro` with its arbitration daemon on this SoC — and `packagegroup-edgefirst-gstreamer` is a single opt-in switch that is not installed. Removes 103 packages here. Both projects move in one commit because the vendor layer's packagegroup references the capability groups added to `meta-edgefirst`.
- Add `meta-edgefirst-phytec` and advance `meta-edgefirst` to `635d4be`: the PHYTEC-specific RAUC wiring — the device keyring bbappend, the bundle signing include, the two bundle bbappends and the CA and publish scripts — now lives in a PHYTEC vendor layer alongside `meta-edgefirst-ezurio` and `meta-edgefirst-torizon`, leaving `meta-edgefirst` vendor-neutral. RAUC is a PHYTEC-only update mechanism, so the keyring bbappend's `update` override matched no other vendor's distro. The new layer also carries the `ClientIdentifier=mac` drop-in that holds a DHCP lease stable across A/B slot activations. Both projects move in a single commit: adding the layer without bumping the pin duplicates every bbappend, and bumping the pin without adding the layer drops the RAUC wiring.
- Document the i.MX 8M Plus / i.MX 95 release-line split in the README: PD26.1.y is published against two Yocto releases, so there is no single Yocto version that tracks it. Records the SoC-to-branch mapping, that each line needs its own workspace because walnascar and wrynose differ in core-layer layout, that a machine config present in a line is not a support claim, and the specific upstream condition under which the two branches could merge.
- New branch `edgefirst-phytec-imx8mp-PD26.1.y`: PHYTEC's `BSP-Yocto-NXP-i.MX8MP-PD26.1.y` manifest (NXP 6.12.49-2.2.0, walnascar) with meta-edgefirst added from `main`, for `phyboard-pollux-imx8mp-3` and `imx8mp-phyflex-libra-rdk-2`. meta-edgefirst's walnascar pseudo 1.9.8 replaces the separate host-fix layer earlier PHYTEC builds needed.
